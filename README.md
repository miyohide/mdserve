# mdserve

ディレクトリ内のMarkdownファイルをHTMLとしてレンダリングし、ローカルWebサーバーとして公開するCLIツールです。WindowsとmacOSの両方で動作します。

## 特徴

- Markdownファイル（`.md` / `.markdown` / `.mdown` / `.mkd`）を見やすいHTMLに変換して表示
- ディレクトリの一覧表示（フォルダとファイルを区別してアイコン表示）
- `index.md` または `README.md` があればディレクトリのトップとして自動表示
- 画像やCSSなどの静的ファイルもそのまま配信
- ダークモード対応のGitHub風スタイル
- パストラバーサル対策により、公開ディレクトリの外へはアクセス不可
- 起動時のブラウザ自動起動に対応（Windows / macOS / Linux）
- ライブリロード対応。Markdownファイルを保存すると、ブラウザが自動で更新される（既定で有効）

## 前提条件

- Node.js 18以上

## セットアップ

依存パッケージをインストールしてビルドします。

```
npm install
npm run build
```

## 使い方

ビルド後、以下のコマンドで起動します。

```
node dist/cli.js [ディレクトリ] [オプション]
```

グローバルにインストールする場合は、プロジェクトのルートで次を実行します。

```
npm install -g .
```

インストール後は `mdserve` コマンドが使えます。

```
mdserve [ディレクトリ] [オプション]
```

### 引数

| 引数 | 説明 |
| --- | --- |
| ディレクトリ | 公開するディレクトリ。省略時はカレントディレクトリ |

### オプション

| オプション | 説明 | 既定値 |
| --- | --- | --- |
| `-p`, `--port <番号>` | リッスンするポート番号 | `3000` |
| `--host <ホスト>` | バインドするホスト | `127.0.0.1` |
| `-o`, `--open` | 起動時にブラウザを自動で開く | 無効 |
| `--no-live` | ライブリロードを無効にする | ライブリロードは有効 |
| `-h`, `--help` | ヘルプを表示する | - |
| `-v`, `--version` | バージョンを表示する | - |

### 実行例

カレントディレクトリを既定ポート（3000）で公開する。

```
mdserve
```

`docs` ディレクトリをポート8080で公開する。

```
mdserve ./docs --port 8080
```

`docs` ディレクトリを公開し、ブラウザを自動で開く。

```
mdserve ./docs -p 8080 --open
```

起動すると、ターミナルに公開ディレクトリとURLが表示されます。表示されたURLをブラウザで開いてください。終了するには `Ctrl+C` を押します。

## ライブリロード

mdserve は既定でライブリロードが有効です。公開ディレクトリ内のファイルを編集して保存すると、開いているブラウザが自動で再読み込みされ、最新の内容が表示されます。エディタとブラウザを並べて、編集結果をすぐ確認したい場合に便利です。

仕組みは次のとおりです。

1. サーバーが公開ディレクトリ配下のファイル変更を監視する
2. 変更を検知すると、Server-Sent Events（SSE）で接続中のブラウザへ通知する
3. 各ページに埋め込まれた小さなスクリプトが通知を受け取り、ページを再読み込みする

ライブリロードが不要な場合は `--no-live` を付けて無効にできます。

```
mdserve ./docs --no-live
```

補足事項

- ライブリロード用のスクリプトは、mdserve が生成するMarkdownのHTMLとディレクトリ一覧ページにのみ埋め込まれます。静的ファイルとして配信するHTMLには影響しません。
- Vimやエディタが作る一時ファイル（`.swp`、末尾が `~` のファイルなど）や `.DS_Store` は監視対象から除外され、余計な再読み込みは発生しません。
- 一部のLinux環境では、サブディレクトリの再帰的な監視に対応していない場合があります。その場合はルート直下のみを監視し、警告メッセージを表示します。

## 動作確認

このリポジトリには `sample` ディレクトリが含まれています。次のコマンドで動作を確認できます。

```
node dist/cli.js ./sample --port 4000 --open
```

## エラーと対処法

| エラーメッセージ | 原因 | 対処法 |
| --- | --- | --- |
| `ポート XXXX は既に使用されています` | 指定したポートが他のプロセスで使用中 | `--port` で別のポートを指定する |
| `ポート XXXX を使用する権限がありません` | 1024未満のポートは管理者権限が必要 | 1024以上のポートを指定する |
| `指定されたディレクトリが見つかりません` | 存在しないパスを指定した | パスを確認して指定し直す |
| `ブラウザの自動起動に失敗しました` | OSのブラウザ起動コマンドが実行できない | 表示されたURLを手動でブラウザに入力する |

## プロジェクト構成

```
mdserve/
├── src/
│   ├── cli.ts      # CLIエントリポイント。引数解析とサーバー起動
│   ├── args.ts     # コマンドライン引数の解析
│   ├── server.ts     # HTTPサーバー本体。ルーティングとファイル配信
│   ├── render.ts     # MarkdownのHTML変換とページテンプレート
│   └── livereload.ts # ライブリロード（ファイル監視とSSE通知）
├── sample/         # 動作確認用のサンプル
├── package.json
├── tsconfig.json
└── README.md
```

## 開発

```
npm run build   # TypeScriptをビルド
npm run start   # ビルド済みのCLIを起動

```

## テスト

テストはNode.js標準の `node:test` を使用しています。追加のライブラリは不要です。次のコマンドで実行します。

```
npm test
```

`npm test` は内部で次の処理を行います。

1. `tsconfig.test.json` を使ってテストコードを含む全ソースを `dist-test/` にコンパイル
2. `node --test` でコンパイル済みのテスト（`dist-test/**/*.test.js`）を実行

テストコードは各モジュールと同じ場所に `*.test.ts` として配置しています。

| テストファイル | 対象 | 内容 |
| --- | --- | --- |
| `src/args.test.ts` | 引数解析 | オプションの解析、バリデーション、エラー処理 |
| `src/render.test.ts` | HTML変換 | Markdown変換、HTMLエスケープ、テンプレート生成 |
| `src/server.test.ts` | サーバー | パストラバーサル判定、実サーバーへのHTTPリクエスト検証 |
| `src/livereload.test.ts` | ライブリロード | 一時ファイル除外、スクリプト注入、SSE経由のリロード通知 |

本番ビルド（`npm run build`）の出力 `dist/` にはテストファイルは含まれません。
